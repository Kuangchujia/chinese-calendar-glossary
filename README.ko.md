### Termonline과의 대응

네 번째 열군(`termonline_*`)은 [Termonline](https://www.termonline.cn/)(전국과학기술명사심정위원회)과의 대응을 준다. **판정 기준**: 그 데이터베이스에 항목이 있고 그 학술 분류가 **천문학**에 속할 때에만 대응을 적는다. 수록된 항목의 **이름이 다르면** 그 행을 `near`로 하고, 그 다른 말을 `termonline_term`에 적는다.

| 대응 | 건수 |
|:---|--:|
| `exact` 같은 이름 | **147** |
| `near` 가까운 이름 | **21** |
| `none` 미수록 | **111** |
| **합계** | **279** |

> **⚠ 영어 두 열은 원 페이지의 축자 전사가 아니다**: **24행**이 개정되었고(제 V 절 참조), 나머지 **255행**은 원 페이지와 바이트 단위로 동일하다. `def_zh` / `tag_*` / `termonline_*`는 **어떠한 변경도 가하지 않고 축자로 재현**한다. `term_en`과 원 페이지 자신의 영어 정의(`def_en`) 두 열에는 제 V 절에 적은 개정이 가해져 있다.

> **데이터 파일 안에 URL은 저장하지 않는다**(이 저장소의 상시 제약). `termonline_term`은 **표제어**만 가지고 학술 분류는 **텍스트**로 가진다. Termonline의 검색 진입점은 <https://www.termonline.cn/>이며, 거기서 표제어를 찾을 수 있다. 이 절충은 한 문장으로 뒤집을 수 있다. 데이터 파일에 URL을 직접 저장하려면 `code/build_glossary.py`의 `parse_termonline()`의 반환값을 바꾸면 된다.

## III. G2–G4 · 분류표와 두 부록

### G2 분류 안내표 —— 원 페이지의 결함 한 가지를 반드시 밝힌다

`classes.csv`는 **원 페이지의** 분류 안내표를 **재현한 것**이다. 대조해 보니 **1급 분류 6개 가운데 5개는 본문의 건수와 한 항목씩 일치하고, "术数择日" 행만 일치하지 않는다**.

| 1급 분류 | 표의 건수 | 실측 건수 | 차 |
|:---|--:|--:|--:|
| 天文基础(천문학 기초) | 90 | 90 | 0 |
| 历法术语(역법 용어) | 56 | 56 | 0 |
| 天象类(천상류) | 36 | 36 | 0 |
| 星宿与星官(성수와 성관) | 50 | 50 | 0 |
| 律历制度(율력 제도) | 33 | 33 | 0 |
| **术数择日(술수와 택일)** | **28** | **14** | **+14** |

**원인**: 그 행의 2급 하위 분류 칸이 **같은 하위 분류 묶음을 두 번** 늘어놓았다 — "择日 5、神煞 8、纳音 1、（＊）择日 5、神煞＊ 8、纳音＊ 1". 별표가 있는 것과 없는 것은 같은 것을 가리키므로 28 = 14 × 2가 된다. 나머지 다섯 분류에는 이런 중복이 없다.

**어느 숫자가 맞는가**: **279**. 네 가지 독립된 증거에 의한다 —
1. **본문의 실제 데이터 행 수**: `<table class="terms">` 안의 데이터 행을 중국어 페이지와 영어 페이지에서 각각 다시 세어 보니 **둘 다 279**;
2. **각 행을 분류 표지로 분류**: 1급 분류 6개의 실측 합계는 **279**;
3. **원 페이지의 각주는 "2급 하위 분류 25개"라고 서술**하며, 실측도 정확히 **25**이고 합계는 **279** — 293과는 양립하지 않는다;
4. **원 페이지의 머리말은 "19개 군 279개 항목"이라고 서술**하며, 사이트 자신의 숫자가 279이다.

이 저장소는 **원 페이지를 고치지 않았다**(사이트 측 변경은 기본적으로 "보고만 하고 실행하지 않는다"). `verification_classes.csv`와 `verification_stated_vs_measured.csv`는 두 숫자를 나란히 보존하고 **"옳은 값"을 결론으로 제시하지 않는다** — 이용자가 스스로 판단할 수 있도록 하기 위해서다. 나중에 원 페이지가 교정된다면 생성기를 다시 돌리기만 하면 된다.

### G3 부록 1 · 이십팔수의 거성을 세 문헌에서 비교

원 페이지는 "각 항목은 영어 페이지와 일대일로 대응하며 어느 쪽에도 빠짐이 없다"고 서술한다. 이 저장소는 그것을 **한 항목씩 실측했다**:

| 지표 | 결과 |
|:---|:---|
| 중국어 페이지의 행 수 | **279** |
| 영어 페이지의 행 수 | **279** |
| 군 수 | **19 / 19** |

## V. 영역: 니덤／사이빈 기준에 따라 원 페이지에 가한 29곳의 개정

**먼저 이것을 밝혀야 한다**: 이 저장소 G1의 영어 두 열은 원 페이지의 **축자 전사가 아니라** **29곳에서 개정**되었다 — `term_en` **6곳**, `def_en` **23곳**, 모두 **24개 항목**에 걸친다. 개정은 「열」 항목까지 포함하여 `data/verification_term_revisions.csv`에 한 항목씩 기록한다. 이 24개 항목을 제외한 **255행**은 원 페이지와 바이트 단위로 동일하다.

### 기준(2026-10-07 제정)

핵심 술어는 **조지프 니덤(Joseph Needham)／네이선 사이빈(Nathan Sivin)의 서양 과학사 기준**을 따른다. 다음 두 조항은 필수다.

| 중국어 | 규정 영역 | 채택하지 않음 |
|:---|:---|:---|

## VIII. 재계산과 재생성

`code/` 아래 세 스크립트(Python 3, **표준 라이브러리만**, 제3자 패키지 불필요):

| 스크립트 | 역할 |
|:---|:---|
| `code/fetch_source.py` | 원 페이지의 HTML을 `_source/`로 가져오고 바이트 수와 md5를 기록한다 |
| `code/build_glossary.py` | 원 페이지를 파싱 → `data/` 아래 모든 파일을 생성한다 |
| `code/verify_glossary.py` | **독립 검증**(판정 기준을 생성기와 공유하지 않는다), 24항목 |

```bash
python code/fetch_source.py --out _source
python code/build_glossary.py --src-dir _source --out data
python code/verify_glossary.py
```

### 생성기의 세 가지 규칙

1. **모든 단언은 디스크 쓰기에 앞선다.** 군 수나 행 수가 다르거나 필드가 비어 있으면 멈춘다 — 어중간한 출력을 남기지 않는다.
2. **모든 숫자는 실측에 의한다.** `len()`으로 세고, 하드코딩하지 않으며, 문서에서 베껴 오지도 않는다.
3. **CSV는 일률적으로 UTF-8 with BOM·CRLF**로 하고, 자매 저장소 `chinese-calendar-dataset`의 기존 파일 규격에 맞춘다.

**멱등성**: 같은 원 페이지를 두 번 실행해도 `data/` 아래 모든 파일의 md5는 동일하게 남는다.

### 검증기의 판정 기준은 생성기와 출처를 공유하지 않는다

`verify_glossary.py`는 **생성기를 import하지 않는다**. 대신 두 곳 — 산출물과 원 페이지 HTML — 에서 다시 세어 맞춘다. 생성기가 "제대로 썼다"고 말하는 것은 근거가 되지 않는다. 아울러 세 가지 단단한 제약을 스스로 점검한다: 데이터 파일 안에 URL이 없을 것, CSV의 인코딩과 줄바꿈이 규격일 것, 플레이스홀더 잔여가 없을 것.

**이번 실행 결과: OK 24 ｜ WARN 2 ｜ FAIL 0**(두 개의 WARN은 제 III 절의 원 페이지 결함의 두 얼굴이다).

### 원 페이지가 개정되었을 때는

원 페이지는 머리에 평문으로 "修订时间: **2026年9月26日**"(개정 시각)를 걸어 두고, 페이지 자신의 JSON-LD는 `datePublished` 2026-09-23, `dateModified` 2026-09-26을 기록한다. 두 페이지의 md5는 `data/source_manifest.json`에 기록하여, 이 데이터가 어느 판의 원 페이지에 대응하는지를 정하는 데 쓴다.
