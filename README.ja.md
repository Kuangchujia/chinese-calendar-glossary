### Termonline との対応

第四の列群（`termonline_*`）は [Termonline](https://www.termonline.cn/)（全国科学技術名詞審定委員会）との対応を与える。**判定基準**：そのデータベースに項目があり、かつその学術分類が**天文学**に属する場合にのみ対応を記す。収録された項目の**名称が異なる**場合はその行を `near` とし、その別の語を `termonline_term` に記す。

| 対応 | 件数 |
|:---|--:|
| `exact` 同名 | **147** |
| `near` 近い名 | **21** |
| `none` 未収録 | **111** |
| **合計** | **279** |

> **⚠ 英語の二列は原ページの逐字転記ではない**：**24 行**が改訂されており（第 V 節参照）、残る **255 行**は原ページとバイト単位で同一である。`def_zh` / `tag_*` / `termonline_*` は**いかなる変更も加えず逐字で再現**している；`term_en` と原ページ自身の英語定義（`def_en`）の二列には、第 V 節に記した改訂が加わっている。

> **データファイルの中に URL は保存していない**（本リポジトリの恒常的な制約）。`termonline_term` は**見出し語**のみを持ち、学術分類は**テキスト**で持つ。Termonline の検索入口は <https://www.termonline.cn/> で、そこで見出し語を引くことができる。この取り決めは一文で反転できる。データファイルに URL を直接保存したければ、`code/build_glossary.py` の `parse_termonline()` の戻り値を変えればよい。

## III. G2–G4 · 分類表と二本の付録

### G2 分類ナビ表 —— 原ページの欠陥を一点、明記しておく

`classes.csv` は**原ページの**分類ナビ表を**再現している**。照合したところ、**一級分類 6 個のうち 5 個は本文の件数と一項ずつ一致し、「术数择日」の行だけが一致しない**。

| 一級分類 | 表の件数 | 実測件数 | 差 |
|:---|--:|--:|--:|
| 天文基础（天文学の基礎） | 90 | 90 | 0 |
| 历法术语（暦法の術語） | 56 | 56 | 0 |
| 天象类（天象の類） | 36 | 36 | 0 |
| <ruby>星宿<rt>せいしゅく</rt></ruby>与星官（宿と星官） | 50 | 50 | 0 |
| 律历制度（律暦の制度） | 33 | 33 | 0 |
| **术数择日（術数と択日）** | **28** | **14** | **+14** |

**原因**：その行の二級下位分類の欄が、**同一の下位分類の組を二度**並べている——「择日 5、神煞 8、纳音 1、（＊）择日 5、神煞＊ 8、纳音＊ 1」。アスタリスクの有無は同じものを指すので、28 = 14 × 2 となる。他の五つの分類にはこのような重複はない。

**どちらの数字が正しいか**：**279**。四つの独立した証拠による——
1. **本文の実データ行数**：`<table class="terms">` 内のデータ行を、中国語ページと英語ページで別々に数え直したところ、**どちらも 279**；
2. **各行を分類標籤で分類**：一級分類 6 個の実測合計は **279**；
3. **原ページの脚注は「二級下位分類 25 個」と述べており**、実測でもちょうど **25**、合計は **279** —— 293 とは両立しない；
4. **原ページの前書きは「十九群 279 項目」と述べており**、サイト自身の数字が 279 である。

本リポジトリは**原ページを改変していない**（サイト側の変更は既定で「報告のみ、実行しない」）。`verification_classes.csv` と `verification_stated_vs_measured.csv` は二つの数字を並べて保存し、**「正しい値」を結論として示していない**——読者が自分で判断できるようにするためである。のちに原ページが訂正されたなら、生成器を再実行するだけでよい。

## V. 英訳：ニーダム／サイヴィンの基準により、原ページに対して行った 29 箇所の改訂

**先にこれを述べておかねばならない**：本リポジトリ G1 の英語二列は原ページの**逐字転記ではなく**、**29 箇所で改訂**されている——`term_en` が **6 箇所**、`def_en` が **23 箇所**、のべ **24 項目**にわたる。改訂は「列」の欄を含めて `data/verification_term_revisions.csv` に一項ずつ記録している。この 24 項目を除く **255 行**は原ページとバイト単位で同一である。

### 基準（2026-10-07 制定）

核心となる術語は、**ジョゼフ・ニーダム（Joseph Needham）／ネイサン・サイヴィン（Nathan Sivin）の西洋科学史の基準**による。次の二条は必須である。

| 中文 | 規定の英訳 | 採用しない |
|:---|:---|:---|
| 干支 | **`Sexagenary Cycle`** | ローマ字 `ganzhi`、逐語訳 `stem-branch`、`Heavenly Stems and Earthly Branches` |
| 岁差 | **`Precession of the Equinoxes`** | 単独の `precession` |

ローマ字は**術語の訳語として用いない**。二十四節気の名はすべて**意訳**する（`Beginning of Spring` とし、そのローマ字表記は用いない。`Awakening of Insects` とし、そのローマ字表記は用いない）。巷間の占い向けの俗訳——`BaZi`、`Four Pillars`、`Eight Characters`——は一切排除する。暦注の実践に触れる必要がある場合は **traditional calendrical teaching materials** と書く。

### 旧い口径は明文で置き換えた

初版（2026-09-29）は「干支」を `stem-branch`、「六十甲子」を `sexagenary cycle` とし、範囲で役割を分けていた。**その分担は 2026-10-07 をもって上表により明文で置き換えられた**——「干支」そのものが `Sexagenary Cycle` である。旧い記述は本節と `data/verification_term_revisions.csv` に**痕跡**として残す。**両者が食い違う場合は本節を正とする。**

> **改訂の実装**：`code/build_glossary.py` に二つの明示的な改訂表——`TERM_EN_REVISIONS`（見出し語の列）と `DEF_EN_REVISIONS`（定義の列）——として書き、各項に `assert`（旧い文字列が期待どおりの回数だけ一致すること）を付け、さらに読み戻しのゲートで両列に旧い形が残っていないか再走査する。**断言はすべてディスク書き込みの前**にあり、改訂はこの二箇所のみで、事後に一項ずつ検証できる。

### 識別子は訳語ではない

## VIII. 再計算と再生成

`code/` 下の三本のスクリプト（Python 3、**標準ライブラリのみ**、第三者パッケージ不要）：

| スクリプト | 役割 |
|:---|:---|
| `code/fetch_source.py` | 原ページの HTML を `_source/` に取得し、バイト数と md5 を記録する |
| `code/build_glossary.py` | 原ページを解析 → `data/` 下の全ファイルを生成する |
| `code/verify_glossary.py` | **独立検証**（判定基準を生成器と共有しない）、24 項目 |

```bash
python code/fetch_source.py --out _source
python code/build_glossary.py --src-dir _source --out data
python code/verify_glossary.py
```

### 生成器の三つの規則

1. **すべてのアサーションはディスク書き込みに先行する。** 群数や行数が異なれば、あるいはフィールドが空なら停止する——中途半端な出力は残さない。
2. **すべての数字は実測による。** `len()` で数え、ハードコードせず、文書から写しもしない。
3. **CSV は一律 UTF-8 with BOM・CRLF** とし、姉妹リポジトリ `chinese-calendar-dataset` の既存ファイルの仕様に合わせる。

**冪等性**：同じ原ページを二度実行しても、`data/` 下の全ファイルの md5 は同一のままである。

### 検証器の判定基準は生成器と源を共有しない

`verify_glossary.py` は**生成器を import しない**。代わりに二つの場所——生成物と原ページ HTML——から数え直して突き合わせる。生成器が「正しく書いた」と言うことは根拠にならない。あわせて三つの硬い制約を自己点検する：データファイル内に URL がないこと、CSV の符号化と改行が規格どおりであること、プレースホルダの残留がないこと。

**今回の実行結果：OK 24 ｜ WARN 2 ｜ FAIL 0**（二つの WARN は第 III 節の原ページ欠陥の二つの面である）。

### 原ページが改訂されたときは

原ページは冒頭に平文で「修订时间：**2026年9月26日**」（改訂時刻）を掲げ、ページ自身の JSON-LD は `datePublished` 2026-09-23、`dateModified` 2026-09-26 を記録している。両ページの md5 は `data/source_manifest.json` に記録しており、本データがどの版の原ページに対応するかを定めるのに使う。
